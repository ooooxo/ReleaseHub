# 布局：Home 用 bento，条目用「图形卡网格 + 折叠/展开两态」，不做瀑布流

用户最初要求 bento + 瀑布流（masonry）。grill 中发现：ReleaseHub 没有真正不等高的内容流，版本号 / 库列表反而需要规整可比；而条目卡（如资源库文件卡）真正的问题是把 [显示名 / 版本 / 简介] 表单 + 6 个操作按钮永久摊开，满屏 input、个体性被淹没——这才是「交互不好用」的根，不是缺瀑布流。

决定：
- **总览（Home）**：bento 布局，按「应用 / 资源库 / 临时文件」分区 + 主次格子，保留每个库的图形化个体性。
- **条目（版本 / 资源库文件）**：图形卡网格 + 两态——折叠态只放身份信息（图标瓦片 / 名称 / 版本胶囊 / 大小 / 简介首行 / 一个主操作），点开就地展开编辑表单 + 次要操作。这是 morii 的 list↔detail 精神，以卡片网格形态承载。
- **临时文件**：收进 Home 的 bento 一格，内嵌拖拽投放区，做到「拖文件 → 就地上传 → 就地出分享链 + 倒计时环 + 一键复制」的单格闭环，不再跳独立创建/详情页（独立详情页仅作深链兜底）。砍掉原「新建跳页→上传→再跳详情拿链」的三段跳转。
- **明确不做瀑布流**：ReleaseHub 内容等高、需对齐，masonry 在此是噱头，硬做会重蹈「交互不好用」。

## Consequences

- 这是对用户初始诉求（瀑布流）的**刻意否决**，记录于此以免日后被重新提起。
- 「折叠/展开两态」是条目卡的统一交互契约，资源库文件卡与版本卡都遵守。
